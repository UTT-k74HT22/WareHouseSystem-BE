# WHS-43 & WHS-44 Frontend Context
## Date: 2026-03-09
## Scope: Purchase Orders header + Purchase Order Lines

## 1. Mục tiêu tài liệu

Tài liệu này khóa context tích hợp FE cho 2 task đã xong business contract:

- `WHS-43`: Purchase Orders CRUD + confirm
- `WHS-44`: Purchase Order Lines mutation

Mục tiêu là để FE xử lý đúng state, ownership field và sequencing giữa header, line, confirm, receipt.

## 2. Tổng quan flow FE

```text
PO List
  -> Create Draft PO
  -> Edit Draft Header
  -> Manage Draft Lines
  -> Confirm PO
  -> Read-only PO Detail
  -> Create Inbound Receipt from confirmed PO
```

## 3. Screen map khuyến nghị

### 3.1 Purchase Order List

Hiển thị:

- `purchase_order_number`
- `supplier_id`
- `warehouse_id`
- `order_date`
- `expected_delivery_date`
- `status`
- `sub_total`
- `tax_amount`
- `total_amount`
- `updated_at`

Actions:

- `Create`
- `View detail`
- `Edit` chỉ khi `status = DRAFT`
- `Delete/Cancel` chỉ khi `status = DRAFT`
- `Confirm` chỉ khi `status = DRAFT`
- `Create receipt` chỉ khi `status in (CONFIRMED, PARTIALLY_RECEIVED)`

### 3.2 Purchase Order Detail

Tab nên tách:

- `Header`
- `Lines`
- `Receipts` sau khi inbound module xong

FE cần coi PO detail là aggregate root:

- header mutate qua `WHS-43`
- line mutate qua `WHS-44`
- confirm qua `WHS-54`

### 3.3 Draft Editing UX

Khi PO là `DRAFT`, FE nên cho:

- sửa header
- thêm/sửa/xóa line
- confirm

Khi PO không còn `DRAFT`, FE phải khóa toàn bộ input mutation và chỉ để read-only.

## 4. State machine FE phải bám

### 4.1 Purchase Order

| Status | FE behavior |
|--------|-------------|
| `DRAFT` | Cho edit header, line mutation, delete, confirm |
| `CONFIRMED` | Read-only, cho tạo receipt |
| `PARTIALLY_RECEIVED` | Read-only, cho tạo receipt tiếp |
| `COMPLETED` | Read-only hoàn toàn |
| `CANCELLED` | Read-only hoàn toàn |

### 4.2 Purchase Order Line

Line không có state riêng trên UI. Quyền mutate line phụ thuộc hoàn toàn vào status của PO cha:

- PO `DRAFT` -> line editable
- PO khác `DRAFT` -> line read-only

## 6. FE sequencing chuẩn

### 6.1 Tạo mới PO

1. Gọi `POST /api/v1/purchase-orders`
2. Điều hướng sang detail draft vừa tạo
3. FE mở ngay vùng quản lý line
4. User thêm line qua `POST /api/v1/purchase-order-lines`
5. Sau mỗi mutation line, FE nên refresh detail PO hoặc local recompute từ response line
6. Khi user bấm confirm, gọi `PUT /api/v1/purchase-orders/{id}/confirm`
7. Confirm thành công thì chuyển PO về read-only

### 6.2 Edit draft PO

1. Load detail PO
2. Nếu `status != DRAFT`, render view-only
3. Nếu `status = DRAFT`, cho sửa header và line
4. Sau create/update/delete line, refresh line list
5. Chỉ enable nút confirm khi đã có ít nhất 1 line ở UI

## 8. UX validation FE nên làm sớm

### Header

- `supplier_id` bắt buộc
- `warehouse_id` bắt buộc
- `order_date` bắt buộc
- `expected_delivery_date` không ở quá khứ
- `currency` nằm trong enum hệ thống

### Line

- `product_id` bắt buộc
- `quantity_ordered > 0`
- `unit_price >= 0`
- `notes` theo max length

FE vẫn phải để BE là source of truth cho validation nghiệp vụ.

## 9. Error handling FE

FE nên map lỗi theo 3 nhóm:

- `404`: entity không còn tồn tại hoặc stale tab
- `400`: sai validation hoặc sai state
- `403`: không đủ quyền

Case quan trọng:

- user đang edit draft nhưng tab khác đã confirm -> mọi mutation sau đó phải reload detail và chuyển về read-only
- line create/update có duplicate product -> highlight product selector
- confirm fail vì không có line -> focus user quay lại tab lines

## 10. Tích hợp tiếp với inbound

`WHS-56/57` sẽ dùng PO detail này như source:

- chỉ PO `CONFIRMED` hoặc `PARTIALLY_RECEIVED` mới tạo được receipt
- `quantity_received` trên PO line sẽ tăng dần từ flow confirm receipt
- FE cần chuẩn bị chỗ hiển thị:
  - `ordered`
  - `received`
  - `remaining = ordered - received`

## 11. Quyết định khóa cho FE

- Header và line là 2 API khác nhau nhưng cùng một aggregate PO.
- FE luôn lấy `status` của header để quyết định quyền thao tác line.
- Không cho user chỉnh tổng tiền và số lượng đã nhận.
- Sau confirm, toàn bộ màn hình PO chuyển sang read-only.
- Từ PO `CONFIRMED/PARTIALLY_RECEIVED`, FE sẽ đi tiếp sang create receipt ở `WHS-56`.
